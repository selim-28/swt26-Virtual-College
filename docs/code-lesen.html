1. 🏭 Factory Method – Erzeugungsmuster (backend_send)

Motivation in einem Satz: Das Fremdsystem soll verschiedene Datenarten (Speiseplan, Auslastung, Abfahrten) erzeugen, ohne dass der aufrufende Code eine if-typ==…-Kette braucht – neue Datenart = neue Unterklasse, sonst ändert sich nichts (Open-Closed-Prinzip).

Analogie: Eine Bäckerei-Kette gibt vor: „Jede Filiale kann backeTagesgebäck().“ Was gebacken wird, entscheidet die Filiale (Brötchen, Brezel, …). Der Lieferwagen (SimulationService) ruft überall nur backeTagesgebäck() – er muss die Sorten nicht kennen.

1a. backend_send/…/simulation/Fremddatensatz.java – das PRODUKT-Interface (18 Zeilen)

package swt2.virtualcollege.send.simulation;
In welchem Paket (Ordner) die Klasse wohnt – Modul „simulation“ von backend_send.
public interface Fremddatensatz {
Ein Interface = ein VERTRAG ohne eigenen Code: Wer „Fremddatensatz“ sein will, MUSS die Methoden darunter anbieten. Im Muster ist das die Rolle „Product“.
    String alsJson();
Die eine Pflicht-Methode: „Beschreibe dich selbst als JSON-Text.“ Nur so kann der Datensatz später als Text über MQTT verschickt werden. Kein Methodenrumpf – den liefern die Produkt-Klassen.
}
Ende des Interfaces. Merke: klein, aber der Schlüssel zur Entkopplung – alle reden nur über diesen Vertrag.

1b. …/DatenGenerator.java – die abstrakte FABRIK (23 Zeilen)

package swt2.virtualcollege.send.simulation;
Gleiches Paket wie das Produkt – das Muster wohnt komplett im Modul „simulation“.

„abstract“ = von dieser Klasse kann man KEIN Objekt bauen (new DatenGenerator() gibt Compilerfehler). Sie ist nur die gemeinsame Schablone der konkreten Fabriken. Im Muster: „Creator“.

Das war die ganze Fabrik-Basisklasse. Prüfer-Vokabeln: DatenGenerator = Creator, erzeugeDaten() = Factory Method, Fremddatensatz = Product.

2. 🔌 Adapter – Strukturmuster (backend_receive/mensa)

Motivation in einem Satz: Über MQTT kommt roher JSON-Text an – unsere App will aber mit sauberen Speiseplan/Gericht-Objekten arbeiten. Der Adapter übersetzt das eine ins andere, ohne dass die App das Rohformat kennen muss.

Analogie: Reisestecker. Dein Laptop (App) will eine deutsche Steckdose (SpeiseplanQuelle); die Wand bietet eine britische (rohe MQTT-Nachricht). Der Adapter macht aus dem einen das andere – Laptop und Wand bleiben unverändert.

2a. receive/…/mensa/SpeiseplanQuelle.java – das TARGET-Interface (13 Zeilen)

package swt2.virtualcollege.receive.mensa;
Modul „mensa“ im Haupt-Backend.

Die Wunsch-Schnittstelle unserer App („Target“): „Gib mir einen Speiseplan.“ Woher – egal.

Eine Methode, ein Versprechen: ein fertiges, sauberes Speiseplan-Objekt. Dadurch könnte die Quelle morgen eine Datenbank oder Testdaten sein – die App merkt nichts.

Wir nutzen Adapter, weil die MQTT-Nachricht ein Fremdformat ist (roher JSON-Text), unsere App aber Speiseplan-Objekte erwartet. MqttDatenAdapter erfüllt das Wunsch-Interface SpeiseplanQuelle (Target) und übersetzt innen die MqttRohNachricht (Adaptee) mit Jackson. Tauscht man die Quelle aus, bleibt die App unverändert – nur ein neuer Adapter entsteht.
„Warum heißt das Adapter und nicht einfach Parser?“ → Ein Parser liest nur Text ein. Das Muster besteht darin, dass die Klasse dabei ein vorhandenes Interface erfüllt (SpeiseplanQuelle), sodass inkompatible Schnittstellen zusammenpassen, ohne eine der beiden Seiten zu ändern – das Parsen ist nur das Mittel der Übersetzung.

3. 🔔 Observer – Verhaltensmuster (backend_receive/pinwand) – läuft LIVE!

Motivation in einem Satz: Bei einem neuen Pinwand-Post sollen alle Interessierten automatisch informiert werden – ohne dass die Pinwand ihre Empfänger einzeln kennt. Bei uns nicht nur gezeichnet, sondern im Live-System: die 🔔-Meldung im Frontend kommt aus genau diesem Code.

3c. …/BenachrichtigungsSpeicher.java – ein KONKRETER Beobachter, LIVE (49 Zeilen)

@Component
Spring-Aufkleber: Diese Klasse wird als Baustein verwaltet und kann injiziert werden – so kommt der Beobachter in den PinwandService.

    static final int MAX_EINTRAEGE = 20;
Obergrenze: nur die letzten 20 Meldungen behalten, sonst wächst der Speicher endlos.
    public record Eintrag(String text, Instant zeitpunkt) {
    }
Ein record = kompakte, unveränderliche Datenklasse: Meldungstext + Zeitstempel. Java erzeugt Konstruktor/Zugriffe automatisch.
    private final Deque<Eintrag> eintraege = new ArrayDeque<>();
Deque = Liste mit schnellem Einfügen VORN – so stehen die neuesten Meldungen immer am Anfang.

    public synchronized void aktualisiere(Benachrichtigung b) {
DER Muster-Aufruf: Das ruft die Pinwand bei jedem neuen Post. „synchronized“ = nur ein Thread gleichzeitig hinein (MQTT-Thread und Web-Threads könnten sonst kollidieren).

MQTT ist sozusagen der „große Bruder“ unseres Observers – beide leben bei uns nachweisbar.

4. 🔐 JWT & Rollen (backend_receive/auth) – die Sicherheitsfragen

Der Ablauf in einem Satz: Login prüft das Passwort (PBKDF2-Hash) und stellt einen signierten Ausweis (JWT) aus → jede Anfrage bringt ihn als Authorization: Bearer-Header mit → ein Filter prüft ihn → die SecurityConfig entscheidet anhand der Rolle, was erlaubt ist.

                .claim("rolle", konto.getRolle())
